## Constraints and proposed implementation

After visual acceptance and separate implementation authorization, adapt `src/scenes/GatehouseScene.astro`, scoped scene CSS and the existing disclosure seam. Reuse Astro, TypeScript/Tailwind, shared layout and the selective Forge React island. Start with native HTML/CSS and one responsive environment plus canonical optimized stills. A future gold treatment must follow an authored conduit mask/geometry with occlusion and reflected light; another thin floating SVG would repeat the failure. Compare this against a locally baked response patch before choosing delivery. Optional motion stays bounded; no continuous glitch rain, particles, parallax engine, new renderer or autoplay sound.

Preserve existing motion preferences and failure behavior, landmarks, skip link, heading/DOM order, visible keyboard focus, Enter/Space activation and existing enhanced Escape/focus return. Decorative art must not intercept input. Target 44×44 px controls; 4.5:1 normal text, 3:1 large text and required non-text boundaries measured on actual composited backgrounds. Verify 200% text and narrow reflow. Image/font/storage failure must retain identity, transmission and links. Keep Human’s prose-first mobile order and approved identity distinctions; [V2.2 Human mobile](../design/phase1-v2-fusion-review/screenshots/human-320-full.png) remains the reference.

**Binding performance limits** from [Creative Direction V2, Engineering](CREATIVE_DIRECTION_V2.md): HTML ≤35 KiB gzip; homepage JS ≤45 KiB gzip; shared CSS ≤25 KiB gzip; fonts ≤100 KiB / two files; Forge JS ≤150 KiB gzip; active environment + character ≤300 KiB mobile / 500 KiB desktop; each pose ≤140 KiB compressed / 4 MiB decoded; decorative decoded images ≤40 MiB. Recorded cold loads: LCP ≤2.5 s, CLS ≤0.1; ≤200 ms interaction is a lab target, not field INP. Attribute decorative tasks >50 ms. Historical mobile long-task concerns remain unresolved. Smaller prompt targets (3.5 KiB HTML, 6 KiB CSS, 60 KiB character) are optimization goals only.

Offline delivery trials measure 63.10–65.91 KiB per pose, 0.67–0.69 MiB decoded; a single environment plus the largest pose is 227.52 KiB mobile / 321.38 KiB desktop in idle. This supports feasibility, **not runtime performance acceptance**. Plates use full PNG character references; these are not delivery assets. If two environments or multiple pose images are retained, count all resident/transfer costs, including at most one adjacent prefetch. [Measurements](../design/phase1-v2-3-handoff/evidence/resources.json).

Preserve `src/content/routes.json`, runtime/public assets, publication/export/output scripts, dependencies, licenses, legacy baseline, canonical masters/provenance and all prior review evidence. Retain `/#meet` compatibility and existing direct destinations in a future slice. `/story` versus `/story/`, `/projects/story/`, `/storytime`, product `/privacy/`, `/site-privacy/`, protected app namespaces and the music-index-only exception remain governed by [deployment gates](DEPLOYMENT_GATES.md). No public asset promotion, build-output release, commit, push or deployment is authorized by this handoff.

## Measurable acceptance and reviewer return

1. **Visual gate first:** owner-reviewed idle, inspection, both acknowledgment alternatives and settled compositions at 1920/1440/768/390/320. With labels hidden, at least 4 of 5 unfamiliar viewers identify Defdef as the operator in idle and point to his input/conductor relationship. At least 4 of 5 distinguish broken versus received signal and understand the Worlds destination after inspection. Record responses, not author inference.
2. **Spatial/canon gate:** all key mechanism anchors and full character survive mobile; no floating feet, severed conductor or gesture into empty space. Pose height/floor-anchor variation ≤2 CSS px at a fixed viewport. Source hashes match; no anatomical or crown changes. Red stays localized within the existing ≤5% initial-viewport limit. Shared shading/light objectives receive explicit visual review; shadows alone cannot clear it.
3. **Static/accessible behavior gate, later:** working no-JS and OS-reduce disclosure, keyboard/touch/focus/dismissal, 200% text, 320 reflow, measured composited contrast, asset/storage failure, direct navigation and Human prose order. Zero applicable automated violations plus manual screen-reader and physical Android/iOS review; automated checks do not replace these.
4. **Engineering/preservation gate, later:** meet documented budgets and recorded cold-load targets, attribute >50 ms tasks, run existing type/build/output/publication and browser checks with approved behavior assertions, and verify protected bytes/ownership. No visual-study PASS implies production approval.

Opus should return a concise annotated judgment: what visibly improved; the smallest remaining material, idle-input and hierarchy corrections; smug versus pointing with image evidence; **REFINE VISUALS AGAIN** or **READY FOR OWNER VISUAL ACCEPTANCE**. Do not reopen Crown Observatory, implement the site or call the design final.
